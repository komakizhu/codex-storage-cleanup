# T1 vault operations

This reference supplements the unified `codex-storage-cleanup` skill for account-specific T1 snapshots, offload, restore, and exact cache or log purges. Follow the parent skill and SOP for discovery, candidate ranking, retention, reporting, and authorization. These operations do not change build locations or schedule themselves. From the child skill directory, use `scripts/vault.py`; inspect its `--help` before an operation. A scan, backup, or skill edit authorizes no local removal.

## Scope and decisions

### Worktree 搬移例外

默认清理中，只有关联组连续超过 168 小时无文件/会话活动且活动、句柄、路径引用、Git 检查全部通过的 worktree 才使用 `move_worktree.py`，不是 `vault.py backup`：完整内容复制并校验到 `/Volumes/T1/Agent/archive/storage-observatory/worktrees/<唯一目录>/worktree` 后，逐条核对引用；组内绝对路径改指 T1 副本，组内相对路径保持同树关系，组外绝对路径原样保留，组外相对路径在 T1 副本中重定位。旧路径软链接是访问别名，不是项目引用或阻断项。核对 HEAD 与搬移前后状态（闲置路线不要求干净），锁定外置登记，最后删除本机副本。定稿只作为候选标记，不能覆盖近期或未知状态；超过 168 小时未活动的未归档会话不单独阻断。以下禁止删除根目录的规则禁止丢弃源码，不禁止这项经过校验的整体搬移。跨卷不能使用硬链接。

每次搬移在目标旁保存 `migration.json`，记录原路径、目标路径、公共 Git 目录和阶段。T1 接上时可直接用原路径；未接时暂不可访问，不自动创建替代目录。公共 Git 元数据留在本机。`git worktree lock` 防止拔盘期间被 prune；需要再次移动或移除时先明确处理该锁。失败在移除原件前回滚，移除阶段失败保留可用 T1 工作树并报告剩余本机暂存路径。不得自动删除历史快照。

- Start with the requested account and exact Codex-owned roots. Use the explicitly requested account home; do not modify another account merely because it is readable. Use `du`, Git status, project configuration, and process/open-file checks to identify complete generated child directories. Never delete a workspace, worktree, repository, `.codex`, `sessions`, or the live `archived_sessions` directory as a whole; the archive-specific operation may remove only verified JSONL children.
- Keep source, Git metadata, lockfiles, essential configuration, credentials, important documents, unique images, and uncommitted work. Back these up when requested, but do not classify them as regenerable. Generated build/test outputs, installed dependencies, virtual environments, SDK downloads, and caches are candidate artifacts only after their provenance and current use are checked. Check visualization directories item by item: they may contain original media, SQLite state, reports, or final outputs.
- Codex-managed `sessions` and the live `archived_sessions` directory must stay on the same filesystem for normal future archiving. Never symlink only `archived_sessions` to another volume, and never delete the live directory itself. By the default cleanup policy, real `.jsonl` and `.jsonl.zst` files older than seven days are backed up to T1, content-verified, and then offloaded individually; recent archives remain local. Offloaded conversations may disappear from Codex's archived-task list or be unavailable to read until restored; explain this after the default action. Do not alter Codex's state DB or pretend that an external snapshot is an automatically readable live archive.
- Before any external write, verify that mounted `/Volumes/T1` is the writable APFS volume with UUID `E70D0032-CFF1-499D-81A2-DA2A661FCAD5` and has enough space. Write new snapshots only to `/Volumes/T1/Agent/archive/storage-observatory/snapshots`. Read, verify, list and restore from the legacy `/Volumes/T1/codex/storage-vault/snapshots` as well; never move or rewrite those historical snapshots. If the disk is absent, short on space, or unsuitable, stop archive deletion and worktree migration; do not substitute a local backup folder. Continue only the default regenerable cleanup that does not require a snapshot, and report the blocked T1 actions. Never create a substitute mount directory. If one snapshot ID exists in both roots, report the conflict and refuse to choose one implicitly.

## Current-account cleanup policy

- On an explicit cleanup run for the current account, inspect `"$HOME/Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation"`. It holds staged app-update packages, not conversation history or source. Use `python3 scripts/vault.py purge-update-cache --confirm-path "$HOME/Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation" --permanent` to remove that exact cache without backup only when no updater is running and no files there are open. If updating is active or its status is uncertain, defer this step and say why. Do not sweep other `Library` caches or perform this mutation during an audit-only request.
- Inspect `"$HOME/Library/Caches/Codex"` separately. It is a browser cache, not the Codex support directory or conversation store. On an explicit cleanup run, use `python3 scripts/vault.py purge-browser-cache --confirm-path "$HOME/Library/Caches/Codex" --permanent` without backup only after the Codex/ChatGPT app has fully quit and no files in that exact cache are open. The command also refuses linked or nested-volume entries. Do not quit the user's app just to make this pass; if it is running, defer and explain that the cache will be regenerated after a later restart.
- Only if the user explicitly requests force-cleaning while the app remains open, use `python3 scripts/vault.py purge-browser-cache-online --confirm-path "$HOME/Library/Caches/Codex" --force-online --permanent`. It removes only six exact `Cache_Data`/`Code Cache` subdirectories after checking that none are open, linked, or on another volume; it leaves the root, active journal files, and non-cache app data intact. This online operation can make the current browser session reload or recreate cache immediately; report actual space recovered. Do not treat a general cleanup request as authorization for this mode.
- Old diagnostic `.log` files under `"$HOME/Library/Logs/com.openai.codex"` may be removed without backup on an explicit cleanup run using `python3 scripts/vault.py purge-old-logs --confirm-path "$HOME/Library/Logs/com.openai.codex" --older-than-days 7 --permanent`. Remove only unopened, regular, user-owned `.log` files whose dated folder and modification time are both older than the retention period; keep recent logs and the directory itself. Say that removed logs will no longer be available for past-incident debugging. This is a small-space cleanup, not a substitute for reviewing large project outputs.
- Inspect old Git-ignored build directories such as `src-tauri/target` per project. For an inactive, verified generated directory that is not the latest keeper, the default cleanup removes its local copy directly without a backup because the source and build configuration can recreate it. Preserve the repository, source, Git metadata, and uncommitted changes. If provenance or active use is unclear, report the exact path instead of deleting it. A later build may recreate it locally unless the project's build output is configured separately.
- A prior ChatGPT application backup under a Codex task's `work/backups` may be kept as a verified T1 snapshot and its exact local duplicate removed only with authorization covering that path and permanent offload, provided it is not the installed app or an active backup target. Do not extend this rule to other backups merely by name. Restore from the snapshot on request, without overwriting an existing local destination.
- `visualizations` and task `outputs` can contain original images, music, PDFs, SQLite state, and final deliverables. For each candidate, report its exact task path, size, notable contents, uniqueness/duplicate evidence, live-use status, and what would be inaccessible after offload. Check apparent duplicate output trees by content, not names or sizes alone; identical files at different paths may still be referenced by tasks, and APFS clones may make `du` overstate recoverable space. Wait for the user's approval of those exact paths before moving or removing anything. Never label all visualizations or outputs as regenerable.
- For specifically reviewed W4DJ tests, audio-reader packages, video App outputs, and old app-patch artifacts allowlisted in `scripts/vault.py`, use a `user-data` snapshot and `offload-reviewed-output` only after the user approves those exact paths in the current task. The allowlist is a safeguard, not standing permission. Preserve neighboring directories, the installed applications, and small source or backup-control files; a final package is not exempt when the user explicitly approves its offload.
- For old application-patch work, inspect the children rather than offloading the `work` root: snapshot each approved large extracted or patched artifact, including single files when applicable, and leave small tools, backup records, and the installed application alone. For `.build`, confirm it is generated, inactive, and Git-ignored where a repository exists; keep dirty source and Git metadata untouched.
- The W4DJ `w4dj-300-short-isolated-20260904-v3` directory has absolute symlinks into `w4dj-300-short-isolated-20260904-v2`. If restoring v3, restore v2 to its original path first; a successful v3 content-signature check alone does not make those links usable.
- Keep ordinary `sessions`, live `archived_sessions` directory, generated images, worktree roots, and application state local unless a separate, app-aware decision covers them. Archive offload follows the dedicated workflow below, not the generic build-artifact rule.

## Audit presentation

When the user asks what can be removed, especially for `visualizations`, present a compact table before seeking approval. Group by task/date, show the largest exact child paths rather than one row for the whole root, and include a remainder row if small items matter. Use current measurements, not the sizes from an earlier audit.

| Candidate (exact path) | Local size | Contents and source evidence | Live use / references | Proposed action and restore cost |
| --- | ---: | --- | --- | --- |
| One reviewed task directory | Measured GiB | Original input, generated copy, state, report; source existence versus content-verified duplicate | Open files, running jobs, unarchived or active tasks, absolute-path links | Keep, cache purge, verified T1 snapshot only, or snapshot then offload; say what stops working until restore |

For apparent duplicates, compare file content rather than names, counts, or equal sizes; source files merely existing on T1 is not content verification. Call out cross-directory symlinks and restoration order. Distinguish a directory's `du` total from the actual free-space change measured with `df` after cleanup, because APFS clones, snapshots, and concurrent writes can change the result. Avoid double-counting parent and child directories. If the user names a space target, state whether the estimate reaches the total target or an *additional* target, and separate immediately purgeable cache from outputs needing exact-path approval. A table is a reporting format, never standing authorization to delete its rows.

## Invocation workflow

1. Give a concise, read-only ledger: exact path, type, size, source or rebuild evidence, Git state, active/open status, proposed `delete inactive update cache`, `backup only`, `backup and evict`, or `archive offload`, and restore cost. Do not infer safety from a name or age. Prioritize large verified generated artifacts. Preserve each workspace and worktree root.
2. Apply the default policy only within an explicit, scoped cleanup request. Running `python3 scripts/apply_cleanup.py --apply` authorizes the three fixed groups for the current user: direct regenerable cleanup, verified T1 relocation of associated worktrees idle for more than 168 hours after all checks pass; a finalization marker never overrides recent or unknown activity (including dirty worktrees when the idle evidence qualifies), and backup followed by offload for seven-day archives or evidence-qualified closed task outputs. A general request to inspect, edit this skill, or back up does not authorize a run. For newly discovered or ambiguous items, especially visualizations and outputs without completion and no-reference evidence, keep them review-only. Never silently expand to neighboring paths.
3. For archive or worktree backup, run the bundled executor or `python3 scripts/vault.py backup --source ABS_PATH --category generated|codex-archives|user-data|worktree`. The script records the source path and a content digest, copies to a new snapshot under `Agent/archive/storage-observatory/snapshots`, and compares source with copy. Verify the snapshot again before any archive eviction.
4. For a verified, inactive, complete redundant generated directory, the default executor permanently removes the exact local directory without a T1 snapshot. It does not create a symlink or change a build tool's configuration. Report that a future build may recreate the local directory unless separately configured.
5. For default archive offload, back up the exact `"$HOME/.codex/archived_sessions"` directory with `--category codex-archives`, verify the snapshot, confirm it contains only regular `.jsonl` or `.jsonl.zst` files and no open files, then run `python3 scripts/vault.py evict-archives SNAPSHOT_ID --confirm-source "$HOME/.codex/archived_sessions" --older-than-days 7 --permanent`. This removes only files older than seven days from the unchanged verified snapshot and leaves the local directory ready for future Codex archiving. Never remove newly added or changed files. Record the offloaded file count, bytes and snapshot ID; warn that those old tasks may not be available in the app until restored.
5a. A finalized marker only makes a worktree a candidate: the entire associated group must still have no file or conversation activity for more than 168 hours, and every handle, path-reference, and Git check must pass. An unarchived conversation whose last activity is older than 168 hours does not block by archive state alone. A verified old-path symlink to an existing T1 worktree is an access alias, not a project reference or blocker. Use the bundled default executor, which calls `move_worktree.py`: inventory every reference, preserve external absolute paths, rebase external relative paths in the T1 copy, repair in-group paths and Git registration, verify the whole copy, preserve staged, unstaged, untracked, and ignored content, lock the external worktree, validate both entry points, then remove the local data copy. A standalone `vault.py backup --category worktree` remains backup-only and does not implement migration. Any recent, open, unreadable, or otherwise unknown group member blocks the group move.
5b. For a closed task output that has an explicit completion marker, is older than seven days, has no unresolved static reference, and is not active, use the exact `user-data` snapshot and offload path. This is separate from immutable worktree migration; a name, age, duplicate-looking content, or output directory alone is insufficient.
6. For ordinary restore, run `python3 scripts/vault.py verify SNAPSHOT_ID`, then `python3 scripts/vault.py restore SNAPSHOT_ID --destination ABS_PATH --confirm-destination ABS_PATH`. Restore refuses to overwrite. To restore archived conversations into the live directory, use `python3 scripts/vault.py restore-archives SNAPSHOT_ID --confirm-destination "$HOME/.codex/archived_sessions"`; it verifies the snapshot and refuses any filename collision rather than overwriting newer archives. Then inspect the app's archived-task list; do not edit its state DB automatically.
7. For the ChatGPT app backup rule, make and verify a `user-data` snapshot of `"$HOME/Documents/Codex/2026-08-31/x20-it-s-a/work/backups/chatgpt-app-20260901-003722"`, then use `python3 scripts/vault.py offload-user-backup SNAPSHOT_ID --confirm-source "$HOME/Documents/Codex/2026-08-31/x20-it-s-a/work/backups/chatgpt-app-20260901-003722" --permanent`. It refuses a changed or open source. Use the no-overwrite `restore` command to recover it. Cache and old-log deletion need no snapshot, but must pass their checks above.
7a. For an explicitly approved, allowlisted visualization or task output, back up that exact file or directory as `user-data`, verify its snapshot, then run `python3 scripts/vault.py offload-reviewed-output SNAPSHOT_ID --confirm-source ABS_PATH --permanent`. It refuses an altered or open source. Restore via the no-overwrite `restore` command; until restored, any task that reads the old absolute path will not find it.
8. Verify the resulting paths and Git status. Report snapshot ID, external location, counts, bytes, digest result, exact local paths removed or retained, actual `df` space change, and how to restore. For an explicitly authorized online browser-cache purge, also report the cache root's remaining size and that open journals were retained; cache may regrow during app use. Leave unapproved and mixed-content directories untouched.

Recurring runs require a separately configured automation and an explicit cadence. The skill itself does not start one. A scheduled run may audit and create requested snapshots; it must not permanently evict newly discovered paths without scoped authorization.
