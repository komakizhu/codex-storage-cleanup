# Codex 当前账号存储清理 SOP

## 0. 目标与总原则

**本机逻辑大小的固定口径：**只加总所选范围内、实际存放在本机内置磁盘上的普通文件逻辑长度（macOS/Linux 的 `st_size`），按设备号与 inode 去重；Windows 按卷与文件 ID 去重。目录遍历和属性读取必须不跟随软链接、macOS alias、junction 或重解析点。链接本身只记录路径、原始目标、目标是否存在和目标卷，目标内容大小不算本机数据。T1 等外置目标默认不读取、不测量；用户明确指定并授权的目标只能作为单独的“外置链接目标”小计，绝不能并入本机总数或本机可释放量。多个硬链接路径只计一份；父子目录汇总不能重复相加。报告把本机逻辑大小、本机文件系统分配量和外置链接目标分开；逻辑大小或分配量都不直接等于可释放空间，APFS 克隆、快照、稀疏文件等影响需单独说明。不得用跟随链接的目录统计值冒充本机占用。

扫描前从系统账号资料确认当前执行账号和 home，只处理该账号。默认扫描本机内置磁盘上已确认属于 Codex 的根：Codex 自身状态/数据目录、受支持的 Codex 应用数据路径、macOS 客户端固定缓存 `Library/Caches/Codex`、更新缓存 `Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation`、日志 `Library/Logs/com.openai.codex`、支持的 Codex 状态或会话元数据精确关联的项目、这些项目登记的 linked worktree，以及有源码或配置证据的 Codex 任务运行数据。固定缓存和日志路径只覆盖上述精确目录，不授权遍历 Library 下的其他目录；清理时仍须通过专用进程、句柄、日期、所有权和卷边界检查。Documents/Codex 与 Documents/ChatGPT 只可用于有限层级的项目入口发现；确认项目来源后才递归该精确项目。默认不递归整个 home、Documents 或 Library；会话曾以大目录为 cwd 也不把该容器纳入扫描。排除 iCloud/CloudStorage、其他账号、外接盘、网络共享和嵌套挂载，不跟随符号链接、alias、junction 或重解析点。T1 上存在工作区、报告、清单或备份不构成扫描授权；范围外引用只记为排除，不计零，也不并入本机占用。

本 SOP 处理 macOS 和 Windows 当前执行账号内、经证据确认由 Codex 生成或管理的数据。不得仅因账号可读取就扫描或修改其他账号。T1 快照、转存与恢复另按 [vault 操作说明](t1-vault-operations.md) 执行。核心目标是：

1. 先从系统账号资料确认当前账号，再解析其 Codex 固定根和元数据关联项目；未确认账号时不开始扫描或处理。
2. 优先识别 Documents/Codex、Documents/ChatGPT 工作区以及 worktree 内占用大的旧构建产物；同组保留最新完整可用的一份。下载缓存默认保留，避免反复下载消耗流量。
3. 对可再生缓存和有来源证据的冗余旧构建，默认按精确白名单直接删除；同一项目保留最新完整可用的一份。
4. 定稿只让 worktree 进入候选；整个关联组仍须连续超过 168 小时没有文件修改和会话活动，并且句柄、路径引用、Git 登记检查全部通过，才默认移动到 T1。定稿本身不能覆盖近期活动或未知状态；任一成员近期活动或证据未知则整组保留。会话是否归档不代替活动时间判断：超过 168 小时无活动的旧会话不单独阻断 worktree。旧路径指向已迁移 T1 worktree 的软链接是访问别名，不是项目引用或阻断项。组内引用要逐条分类；内部引用修复，外部绝对引用保持原值，外部相对引用在 T1 副本内重定位。只有无法解析的组内引用或无法保留目标语义的链接阻止该组。脏、已暂存、未跟踪和无 HEAD 的 worktree 只要属于有证据的长期闲置组，也必须完整保留并支持恢复。超过 7 天的归档会话，以及已结束、完成标记明确且无未解析引用的旧任务成果，先备份并校验，再只删除对应旧文件。
5. 每个动作都要能说明：属于哪个用户、为什么属于 Codex、为什么现在可以处理、如何恢复、清理后如何验证。

“看起来很旧”“目录名像 cache”“位于 Documents”“磁盘占用很大”都不能单独证明可以删除。目录名、修改时间和大小只能作为候选信号；默认动作还必须通过来源、可再生性、使用状态和执行前的精确路径复核。

## 1. 不可违反的边界

默认不读取 `~/Library/Mobile Documents` 和 `~/Library/CloudStorage` 云同步目录及其本地缓存。云目录引用按范围外保留；不得因为范围外引用而推断本机没有引用，也不得仅以“目标在扫描范围外”阻止无关 worktree。
已迁移到 T1 的旧路径软链接是访问别名，不进入项目引用图。其他组内引用逐条核对：组外绝对路径保持原值，组外相对路径在 T1 副本内重定位；只有组内引用无法解析或目标语义无法保留时才阻止该组。虚拟机挂载或句柄别名未解析时仍保持未知。

符合上述 168 小时闲置及全部检查条件的定稿 worktree，其完整校验搬移是下文“根目录保留”的明确例外：源码和工作资料完整保存在 T1，旧路径保留软链接，公共 Git 元数据保留本机；成功后删除本机数据副本以释放空间。定稿标记不能覆盖近期活动或未知状态，也不能把源码当可再生缓存丢弃。迁移目录使用 `worktrees`，不能把可继续编辑的工作树放进不可变 `snapshots`。按目标路径去重，迁移目录内已计入的旧构建不能重复累加。

- 不把 mac1、其他机器或未知来源的备份混入当前目标。
- 不删除工作区或 worktree 根目录、活动会话、正在运行的任务、用户文档、项目源代码、配置、锁文件、数据库、认证文件或未知目录。未提交内容不因脏状态直接进入删除；符合长期闲置迁移条件的 worktree 必须完整搬移，而不是删除其中的代码或资料。
- 不清空废纸篓/回收站，不删除 APFS、Time Machine 或 Windows 系统恢复点，不修改权限，不为清理而关闭安全软件。
- 不用整个 Documents、Downloads、用户主目录、C:\Users、C:\ 或根目录作为删除目标。
- 不使用宽泛的 rm -rf、Remove-Item -Recurse、通配符或未解析的 $HOME、~、%USERPROFILE% 作为最终删除目标。
- 不因为当前用户具有管理员权限就默认读取或删除其他用户的数据；权限不足时记录并报告，不用提权绕过判断。
- 默认清理只允许执行三类固定动作：有真实来源证据的可再生内容直接删除；关联组连续超过 168 小时闲置且活动、句柄、引用和 Git 检查全部通过的 worktree 移动到 T1；定稿标记不能覆盖近期或未知状态；超过 7 天归档及证据充分的已结束任务成果先备份后删。其他路径仍需单独授权；不得扩大到父工作区、worktree 根或相邻路径。

## 2. 用户与平台盘点

### 2.1 先确认当前执行账号

记录当前操作系统和执行账号，并通过系统账号数据库核对用户名与 home；不得只信任 `$HOME`、`USERPROFILE` 或目录名。执行账号或 home 与目标不一致时停止，不遍历 `/Users`、`C:\Users` 或其他账号目录。

只建立当前账号的一条范围记录：

| 字段 | 要求 |
|---|---|
| 平台/账号 | 真实 OS 和系统账号标识 |
| 主目录 | 解析后的绝对路径 |
| Codex 根 | 实际存在且有固定路径或来源依据的 Codex 目录 |
| 可读性 | 完整、部分受限或不可读 |
| 活动状态 | 是否有 Codex、agent、构建或编辑器进程使用 |
| 处置范围 | 仅查看、可列候选、已获授权 |

### 2.2 用户级 Codex 路径

不同版本和安装方式可能使用不同位置，以下是探测范围，不是无条件删除白名单：

| 平台 | 优先探测 | 处理要求 |
|---|---|---|
| macOS | 用户主目录/.codex | 逐项识别 archived_sessions、sessions、worktrees、缓存、日志、临时目录和元数据 |
| macOS | 用户主目录/Documents/Codex 与 Documents/ChatGPT | 仅作有限层级入口发现；递归扫描前必须确认精确项目来源 |
| macOS | 用户主目录/Library/Application Support 下实际存在的 Codex 目录 | 先确认产品归属；数据库、认证和设置默认保留 |
| Windows | 用户主目录\.codex | 逐项识别与 macOS 对应的会话、worktree、缓存、日志和临时数据 |
| Windows | 用户主目录\Documents | 仅作有限层级入口发现；递归扫描前必须确认精确项目来源 |
| Windows | 用户主目录\AppData\Local 或 Roaming 下实际存在的 Codex 目录 | 先确认产品归属；设置、凭据、数据库默认保留 |

在执行动作前，把环境变量、快捷方式、符号链接、macOS alias、Windows junction/reparse point 都解析为真实路径；删除校验必须针对真实路径，并拒绝越过当前账号 home、已确认 Codex 根或允许的内置卷范围。

## 3. 统一分类模型

将每个发现项归入以下一类，并在报告中保留原始路径：

### A. 受保护的活动/核心数据

包括工作区/worktree 根目录、活动会话、正在写入的日志、当前任务、未提交代码、用户文档、配置、锁文件、数据库、认证文件、项目资源和任何正在被进程打开的文件。默认不删除。

### B. 可再生成且有来源证据的候选

包括确认属于 Codex 或 Codex 任务的缓存、临时目录、旧日志、构建缓存和完整构建目录。默认执行只覆盖路径存在、非链接/重解析点、未被使用、可重新生成且落入精确白名单的缓存与旧构建；旧日志等其他项仍需单独处理。

### C. 高风险的用户数据候选

包括归档聊天、已关闭会话、工作区内可能含用户数据的混合旧产物、导出文件、附件和下载内容。归档会话只有超过 7 天的真实 `.jsonl`/`.jsonl.zst` 文件进入“先备份再删”默认组；最近归档、普通 sessions、附件和其他用户数据默认保留。

### D. 未知/系统/第三方数据

包括无法确认来源的目录、系统目录、其他应用数据、恢复点和权限受限内容。只报告，不清理。

## 4. Codex 工作区内的旧产物（不删除工作区）

Documents 中的 Codex 工作区、Codex worktree 根目录、源代码和 Git 元数据属于受保护容器。本 skill 只清理容器内部已经确认的旧产物，不删除工作区本身。

“Documents 里是 Codex 建的”仍必须有可验证的来源。优先寻找以下证据：

- Codex 配置、任务元数据、会话记录或工作区清单明确引用该绝对路径。
- 目录包含能指向 Codex 任务或生成流程的项目元数据、日志、manifest 或关联标识。
- 该目录位于用户明确配置的 Codex workspace 根下，且目录内容与任务记录相互对应。

只有名称相似、位于 Documents/Codex、创建时间接近某次任务，不能作为唯一证据。没有强来源证据的父目录归入“未知/需用户确认”，不向下扩大清理范围。

对于每个候选旧产物：

1. 同时记录父工作区和待处理的精确子路径、用户、项目、来源证据、大小、时间和最近使用线索。
2. 检查子路径是否被 Codex、编辑器、终端、构建工具或其他进程使用；父工作区是否为当前任务。
3. 记录父工作区的 git status --short。工作区存在未提交源代码时，不得删除源代码或混合目录；如果子路径已证明是独立、完整、可再生成的产物，脏 Git 状态本身不扩大保护范围，也不能替代子路径证据。
4. 区分构建输出、缓存、临时文件、日志等可再生成内容与用户源文件、文档、资源、下载及配置；无法区分时按高风险数据处理。
5. 即使产物看起来没有用，也要在清单中显示精确子路径；默认执行只处理已经完成源码/配置/使用状态核验的旧构建，其他混合目录继续等待单独授权。

用户只授权旧产物时，不得扩大为删除工作区；用户只授权某个工作区内的产物时，也不得处理其他用户、其他项目或父工作区。

### 4.1 工程外运行数据与目录累计统计

固定 Codex 根目录之外的应用运行数据必须通过受支持的应用标识、固定相对路径和可读取的来源/配置证据关联。当前映射覆盖腾讯语音、Pet Studio、MusicCardProbe、MacDiskCheck、W4DJ、Codex 日志和 Codex 运行时；映射结果明确写出 `current`、`historical-missing`、`unknown` 或 `confirmed-unrelated`，并保留精确证据路径。当前目录只有固定应用标识/路径而没有源码或配置读取证据时，必须同时写出 `association_status=provisional`、`evidence_status=mapped-only` 及缺少原因；它可以帮助解释目录用途，但不能写成已确认来源、闲置或自动清理对象。名称相似、目录年龄和 T1 上已有同名目录只提供线索，不能确认归属、活动状态或迁移完成；共享依赖默认仍是共享依赖。

目录级统计复用同一次文件清单，只在已确认 Codex 根和关联项目根内选择不重叠汇总边界。硬链接按文件身份去重；逻辑字节、分配字节、未知的实际可释放量分别报告。目录累计量不受单文件 100 MB 展示阈值限制，所有行都显示来源、用途、覆盖状态、活动状态、保留项、恢复代价和处置建议。处置类别固定为「本地保留」「T1 工作数据」「归档候选」「可再生清理候选」「暂不处理」；未知、活动未检查或验证失败的目录的有效类别只能是「暂不处理」，计划路线另列且不得进入清理白名单。

### 4.2 清理收益和恢复代价

先查 Documents/Codex、Documents/ChatGPT 中有来源证据的项目，再查 worktree。worktree 发现必须同时覆盖 `~/.codex/worktrees` 和已确认项目根目录下 `.worktrees` 中登记的 linked worktree；`.worktrees` 从普通产物递归中排除，避免把其中的构建目录与整棵树重复计算。扫描阶段完成源码入口、workspace 成员、构建命令、Git 忽略规则与编译器/框架产物结构核对：确认是可重建的完整编译输出后，按项目保留最新一份，其余明确建议删除并计入推荐清理量。目录名只确定探测范围，不能单独证明可删。优先处理大产物，不把小缓存放到第一位。

每项说明：建议删的精确路径、保留的最新路径、源码入口与构建命令、源码版本、重建成本与联网可能。用户看到的是“建议删 A，保留 B；A 是编译输出，源码在 C，需要时用 D 重建”。不要求旧新产物功能完全等价或历史日志齐全，也不把分支不同、耗时未知当成保留理由。扫描器尚不支持的构建器由 agent 在同一轮继续读取配置核实；只有源码缺失、混入用户文件或无法确认目录用途等具体问题才能列入未确认项。

生成图片、聊天、附件、独有报告和导出物默认保留。重新调用图片/模型 API 并不能复现同一份产物，且可能消耗费用和流量；它们不能按构建产物套用“只留最新”。

## 5. 会话和归档数据

### 5.1 归档会话

对 archived_sessions 或平台上等价的历史归档目录：

1. 先确认用户、真实路径、所有权、非链接状态和目录归属。
2. 只把真实 `.jsonl` 和 `.jsonl.zst` 文件中 mtime 超过 7 天的文件列入默认组；最近文件、旁车文件和非预期条目保留。
3. 先把整个 `archived_sessions` 目录复制到 `/Volumes/T1/Agent/archive/storage-observatory/snapshots`，用 manifest、文件数量、总字节数和内容级校验比较源与备份。macOS ExFAT 旁车文件如 `._*` 不计入真实聊天数量；Windows 元数据文件也要与真实聊天文件分开记录。
4. 校验失败、源正在写入、文件集合发生变化或 T1 不可用时，停止该组删除并保留源。
5. 校验成功后只删除超过 7 天的精确文件，不触碰 `sessions`、配置、最近归档和整个 Codex 根。
6. 删除后验证 T1 备份仍可读、旧文件数量/字节数与删除前选择一致，并报告恢复可能需要应用重建本地索引。

### 5.2 当前或普通会话

sessions、运行时日志和锁定文件默认视为活动数据。不能仅凭文件年龄批量删除。只有在产品格式或明确元数据能证明某个会话已关闭、无写入、无索引依赖，并且用户另行选择了精确路径时，才可列为额外候选；普通 sessions 默认仍保留。

## 6. 缓存、日志和临时文件

默认保留需要联网重取的内容：Cargo registry（包、索引和源码）、Cargo git 下载缓存、Rust 工具链、npm/pnpm 包仓库、node_modules、Python 虚拟环境、模型下载和 Codex 插件包。它们可以重新下载，但会增加流量、安装和下次编译成本；不计入默认推荐清理量。只有用户另行要求处理这些缓存时才按精确范围评估。

Cargo `target` 是编译产物，不等同于 Cargo registry/git 下载缓存。旧的冗余 target 可按 §7 评估；最新有用 target 及其增量编译状态默认保留，不拆删内部对象文件。

优先产物处理完后，默认直接处理已确认无活动使用、恢复成本低且落入白名单的 Codex 临时目录和应用缓存。旧日志、未知缓存不能仅因名字而视为低成本，仍需单独评估。

可检查 cache、caches、tmp、temp、旧诊断日志、下载中间文件和明确标记为可重建的 Codex 目录，但必须同时满足：

- 路径属于某个已确认的 Codex 安装或 Codex 任务。
- 不是设置、认证、数据库、索引、锁文件、用户附件或唯一输出。
- 没有 Codex、构建或编辑器进程使用。
- 删除后产品可以重新生成，且不会丢失用户意图、项目源文件或聊天历史。
- 路径被列出并由默认清理入口在执行前重新核验；不在默认三类范围的路径仍需单独授权。

优先按完整的缓存/临时目录处理，不在内部随意挑删数据库页、对象文件或工具缓存碎片。无法证明可再生的日志和附件归入高风险候选，而不是绿色自动清理项。

## 7. Worktree 与旧构建产物

### 7.1 候选目录

在已确认的 Codex worktree 或 Codex 生成工作区内，检查：

- Rust/Cargo：target、src-tauri/target
- 前端：dist、build、.vite、.next、out
- 工具缓存：项目内明确归属的 .cache、coverage、构建器缓存
- 其他构建目录：只有项目配置或构建日志明确表明它们是可再生成产物时才纳入

不要在整个用户 Documents 或整个磁盘上按目录名批量匹配。target、build、dist 等名称本身不是 Codex 归属证明。

### 7.2 保留与删除判断

按用户和项目分组，每组默认留最新已完成的一份，并额外保留正在使用或用户指定保留的目录。只剩一份就保留。新构建失败/不完整时，保留最近存在可执行文件、库或框架完成标记的一份。使用这些实际输出的时间选最新，不用父目录 mtime。不同分支、提交、debug/release 和架构不自动拆成保留组；源码还在，旧配置需要时可以重建。

扫描器核对源码、构建配置和生成目录结构，给出恢复命令；这是可重建性静态核查，不是假称重新编译已经通过。不额外编译或下载做盘点。重建耗时未测量就明确写出；保留依赖缓存，缺少依赖可能需要联网时如实说明，不因为耗时未知就排除可重建大产物。

普通 `target`、`build` 可能同时包含多种配置或架构。选中为最新保留目录时整个保留；属于其余可重建目录时整个建议删除。识别自定义 `target-*` 和配置指定的输出根，禁止把内部 `debug/build` 当作独立候选或重复统计。不得手拆 incremental、对象文件或内部缓存。

用 Git common-dir 或同源仓库地址识别同项目的 worktree/副本；不同用户分开。同名但不同仓库不能合并。活动产物暂留，Git 脏状态只保护改动的源文件和混合目录，不禁止清理独立的生成目录。

只有同时满足以下条件的完整目录才可进入默认直接删除清单：

- 路径位于已批准的 Codex 工作区内，解析后不是链接或重解析点。
- 该产物目录没有被运行程序或构建进程使用；项目仍在开发不意味着所有历史构建目录都必须保留。
- 目录是完整的可再生成产物，不是源代码、资源、配置或用户输出。
- 同一用户/项目保留最新已完成的产物目录，记录精确路径和实际输出证据；或用户明确授权不保留该项目的产物。
- 删除整个已确认目录，不手工挑删单个 .o、.rlib、incremental 或其他内部文件。

只有整个关联组连续超过 168 小时没有文件和对话活动，且没有活动、打开状态未知或不可读证据时，才进入搬移清单。定稿只是候选标记，不能覆盖近期活动或未知状态。尚未归档但活动时间超过 168 小时的会话不单独阻断。已迁移 worktree 的旧路径软链接不算项目引用，不阻断其他组。搬移前逐条分类相关引用：组内目标按迁移映射修复，外部绝对路径原样保留，外部相对路径在副本中重定位，旧路径软链接供原有引用继续访问。只有无法解析的组内引用或不能保留语义的链接阻断该组。搬移成功后移除本机副本并计入预计释放量。Git 状态干净、已有提交不再是唯一入口；脏、已暂存、未跟踪、忽略内容及无 HEAD 情形必须由 `move_worktree.py` 完整保留、校验和恢复。公共 Git 元数据与跨目录引用一并检查。

### 7.3 全面发现、归属与未知大项

来源提取只读取明确 Codex 数据源：全局状态、项目配置和会话 `session_meta` 白名单字段；不递归把工作树、skill 或依赖中的 `state.json`、`tsconfig.json`、`Cargo.toml` 当作全局状态。配置相对路径以来源文件目录为基准，会话相对 cwd 无可靠基准时保留为未解析引用。可写范围不是 Codex 来源证明；显式文件引用不得扩大为整个父目录。每条引用保留来源、字段、身份、时间、路径基准和存在/缺失/范围外/不可读状态。历史引用保留为线索，不产生占用，缺失和范围外提示不等于遍历失败。

测试文件名只用于定位候选。确认批次需要运行身份、计数或产物结构等内容证据；普通配置、夹具和散落日志单独报告，不建立主目录测试批次。JSON Lines 即使使用 `.json` 扩展名也按内容识别，JSONC 用词法处理注释与尾逗号，拼接对象可恢复但记录格式提示，坏行/截断/预算不足/变化必须保留缺口。完成状态只能由同一身份的有序、稳定事件判断，不能用日志关键词推断；项目归组不代表批次可替代。

覆盖报告按遍历、来源提取、项目关联、测试分析、虚拟机依赖和重复校验分别标注 complete/partial/unchecked，并区分原始事件数、唯一诊断数和唯一路径数。诊断按阶段、代码和路径归组但保留全部来源明细。旧台账缺少阶段信息显示未检查，不补成完整。权限失败仍为真实缺口，验收不以错误数降为零为目标。来源引用、非运行候选和诊断始终只读、删除路径为空。

默认 `full` 表示当前账号全部已确认 Codex 根的全集，不表示遍历整个主目录。扫描根只从 Codex 固定路径、受支持状态/会话元数据中的精确项目路径、项目登记的 linked worktree，以及有源码/配置证据的任务运行数据产生。Documents/Codex 和 Documents/ChatGPT 仅用于有限层级的入口发现；确认精确项目后才递归。会话 `cwd` 指向 Documents、Library 或其他大容器时，不纳入容器本身。显式 `--root` 必须是已确认根内的真实目录；它把扫描标记为子集，不能冒充全集或扩大范围。

遍历、容量、文件计数、worktree 文件活动和静态引用候选共用本轮新建的文件清单；来源状态、活动索引和相同 Git 查询在本轮复用。引用文件仍按受支持规则逐条读取和解析。每个根记录来源依据；iCloud/CloudStorage、其他账号、外置卷、嵌套挂载和链接目标只记录排除原因，不读取或计入本机占用。权限失败、读取失败、跨卷边界、超时和中断都保留为未知/覆盖缺口。

完整清理扫描共享 1200 秒预算，外部命令使用剩余时间。计时覆盖账号核验、来源发现、文件清单、归属/引用分析、清理计划和报告数据准备。预算耗尽、根发现不完整或任何覆盖缺口都不能标记为完整验收；执行入口必须在此时停止，不执行删除、备份或迁移。T1 复制、校验和动作后复测单独计时，不计入 1200 秒扫描预算。

项目归组按以下顺序保留证据：Codex 全局状态/线程元数据中的工作目录，明确配置和 manifest 的绝对引用，Git common-dir 或规范化仓库来源，以及显式跨目录引用。目录名、日期、版本号和批次名只能产生低置信度候选，不能把同名不同项目合并。归组不等于结果可替代：同项目的多个组件、配置和运行批次仍必须分别记录完成状态、输入、模型、数据库、结果、中间文件和依赖。

重复分析先按大小筛候选，再执行稳定 SHA-256；校验前后文件标识、大小或修改时间变化时撤销该项重复证据。硬链接按文件标识只算一个实体并保留所有路径。外置盘软链接目标绝不计入本机目录或本机汇总；目标若获准检查，容量独立列出。内容重复只计算“保留一份后的多余逻辑字节”，实际分配空间受 APFS 克隆/快照影响时标为未知，不转成可释放量。

虚拟机/容器检查识别 UTM、Parallels、VMware、VirtualBox、QCOW、VHD、VMDK、RAW、稀疏镜像、分片、父盘/差分盘和快照元数据，并只读解析可识别的依赖关系。报告进程、打开/挂载状态和检查缺口；运行中、已挂载或状态未知的镜像不进入已确认重复量。`.img`、`.bin` 等通用扩展名没有文件头或配置证据时只作为未知大项报告，不直接认成虚拟机。

全面发现产生的记录只能进入发现报告，`trash_paths` 必须为空；服务端在载入台账时再次拒绝这些记录进入任何删除白名单。报告同时展示本机逻辑大小、本机分配大小、已确认 Codex 占用、归属不明占用、重复逻辑量和现行规则下的清理候选，父目录与子文件不重复相加；外置链接目标如获准测量，放在单独小计并明确注明“未计入本机”。不得将外置链接目标与本机数据合并成一个总数。

旧 worktree 根本身含有代码和 Git 元数据，始终不是本 skill 的直接删除对象。只对其内部已确认的完整构建目录、缓存或临时目录列安全删除候选；工作树整体只有在关联组连续超过 168 小时闲置且引用、活动和 Git 恢复证据齐全时才能迁移到 T1；定稿标记不能覆盖近期或未知状态。迁移不要求干净状态，但不得把未提交或未跟踪资料丢进普通备份或删除路径。

### 7.4 从容量清单追查到具体用途的固定方法

用户要求查账、查原因或想办法时，默认只读调查，不改程序、测试、配置或 Skill，不安装、不运行被调查的工具、不清理。明确要求更新 Skill 时只更新说明；明确要求实施时才修改对应程序。以下步骤在已授权范围内自主完成，不反复询问是否继续，也不要求用户替 agent 判断文件用途。

1. **固定范围和原账。** 记录扫描时间、账号、内置磁盘范围、原始字节口径，以及本轮是全量还是某个子集。历史清单和实际文件分开记录，读取任务明确指定的历史清单不授权扫描其所在外接盘。
2. **精确找回所有实体。** 从原始逐文件清单还原该子集，沿用原扫描的文件身份去重规则，保留硬链接路径但只计一次。不能只检查汇总中的几个样例就声称已逐项检查；输出实体总数及原始字节和，核对与待查子集一致。零字节文件保留数量，不因体积小而漏掉配置、标记和锁文件。
3. **检查当前对象。** 对每个目标核实实际卷、链接、存在性、可读性及大小，限定读取必要文件头；不跟随链接越界，不扫描邻近的其他盘。文件头确认格式，不自动证明来源、用途或可删除。被删除、变大或仍在写入的对象单列变化，不把当前大小替换进历史账冒充对平。
4. **从大到小补用途证据。** 结合完整任务根、上级目录、组件清单、同目录源码、下载／生成脚本、输出结构和测试代码追查。共享状态归工具，独立任务用完整工作目录区分，依赖归所属任务或工具；没有 Git 身份不等于来源不明。同名不同路径的任务不能自动合并。
5. **区分证据层级。** 分别写明“格式已验证”“源码／清单对应”“根据目录及名称推断”。读过文件头不等于逐字读过全部内容，发现同名源码不等于证明二进制与源码完全一致。对仍只有泛化标签的项继续追查；真实的权限或历史证据限制如实说明，不编造、不补零。
6. **归类并对账。** 每个实体只归入一个本轮汇总组，说明是什么、为什么产生、属于哪个任务或用途。原始字节先求和再换算两位小数；分类和必须等于原账。逻辑大小、文件分配量和可释放空间分别处理，不能互相替代。未完成项不能从分母消失。
7. **直接在对话交付。** 先给位置／任务版表格，再按需要补用途分类版。说明核查范围、证据、对账结果、当前变化和实际动作。归类或核实用途不增加清理授权；不以文件链接、附件或外部报告替代回答。

按内容选择只读验证方法，不仅按扩展名判断：

| 对象 | 核实方法 | 用途及产生原因如何确认 |
|---|---|---|
| 无扩展名程序 | 检查 Mach-O／ELF 文件头和平台架构 | 查配套源码、包内位置、调用脚本；区分设备调试工具和任务自编辅助程序，不执行程序 |
| 改名的数据库伴随文件 | 核对 SQLite、WAL 文件头、共享内存结构及同组数据库 | 查数据库操作／恢复脚本，判断是应用运行状态还是修复实验留存；不能因为带 live 字样就声称当前在用 |
| 卡包及其他压缩交付物 | 只读查看归档成员，适度校验压缩包完整性，不解压执行 | 例如卡包中的 collection.anki2 和媒体清单证明是制卡成果，不是缓存 |
| 浏览器组件和二进制配置 | 读取组件 manifest、版本与文件结构 | 区分过滤规则、安全配置、功能配置和模型权重；有模型名称的配置文件不是模型本体 |
| 依赖包的小文件 | 读取 METADATA、WHEEL、RECORD、许可证、类型声明和入口结构 | 对应包名、用途及所属虚拟环境，解释由依赖安装产生，不把每个依赖当成独立项目 |
| 状态临时文件 | 验证 JSON／plist 等格式和字段结构，不输出私密值 | 与正常状态文件的结构比较，说明是状态保存中间副本；没有日志证据不臆断崩溃原因 |
| 测试夹具、硬链接及标记 | 查看创建它们的测试代码、标记内容和文件身份 | 确认是模拟测试资料还是实际用户数据，硬链接按同一实体统计 |
| 交接包、校验清单、补丁 | 验证 Git bundle、补丁结构和摘要行格式 | 归为迁移／恢复资料；校验清单格式正确不等于已核验其所有目标文件内容 |
| 下载分片 | 查下载脚本中的分片命名、区间和合并逻辑 | 对应具体模型或下载任务，不能凭 .part 后缀认定下载成功或分片可删 |

不输出凭据、Cookie、口令或健康等用户私密内容；只汇报验证所需的结构和用途。遇到真实阻塞先查现有记录和相邻证据，只在需要新增授权或用户独有信息时集中提问。不得为消除分类空白而改变来源事实或降低删除保护。

## 8. 清理前候选清单与授权

默认在 Codex 对话中直接给出概览，不要求用户打开 HTML：可再生缓存、编译缓存、可重建中间文件和冗余旧构建直接列为默认安全清理量，构建产物仍给出“每项目保留最新完整可用一份”和“一份也不留”两个互斥方案，各显示 GB 数和差额；归档会话与已核实结束的旧任务成果另列“超过 7 天、先备份再删”的文件数和字节数；关联组连续超过 168 小时闲置且所有检查通过的 worktree 列为 T1 工作数据；定稿标记不能覆盖近期或未知状态。会话记录、未完成或引用不明的生成图片和输出另外显示占用，默认保留，不归为可删缓存。HTML 与精确路径台账仅作为补充。

“一份也不留”仅针对已核实可重建的构建产物，包含默认保留的最新目录；源码、依赖和 Cargo 下载缓存不在此范围。计算方式为：全删构建估算 = 已核实构建目录总量 - 已知正在使用部分；使用状态未检查的部分单独注明。两个方案不能相加；估算第二方案不能扩大默认删除白名单。询问“全删能清多少”只要求估算，不是执行授权。

执行默认清理前，先输出候选清单；运行 `scripts/apply_cleanup.py --apply` 即表示用户选择这三类默认策略：

| 建议与优先级 | 用户/平台 | 拟删精确路径与大小 | 保留最新路径/替代证据 | Codex 来源与源码/重建命令 | 联网/重建成本 | 活动/Git 状态 | 风险/恢复 |
|---|---|---|---|---|---|---|---|

先给结论：“建议直接删除有证据可重建的旧产物 X，保留最新完整构建 Y 和下载缓存 Z；超过 7 天的归档会话及已结束旧任务成果先备份到 T1 再删；关联组连续超过 168 小时闲置且所有检查通过的 worktree 搬到 T1；定稿标记不能覆盖近期或未知状态，校验后移除本机副本并保留原路径软链接”。扫描完成时必须已对支持的构建类型作出删除/保留决定，不能把整批大目录都留在草稿中。推荐旧产物量、备份后删除量、T1 迁移量、具体未确认项和保留量分别统计；按文件身份、路径和硬链接去重，区分预计释放与实测释放。永久删除按实际可用空间变化核验。

候选清单必须区分：

- 只读检查项；
- 先备份到 T1 再删除的超过 7 天归档项和证据充分的已结束任务成果；
- 可永久删除的、明确可再生成的项；
- 移动到 T1 并以原路径软链接访问的关联组连续超过 168 小时闲置且所有检查通过的 worktree；定稿标记不能覆盖近期或未知状态；
- 因权限、来源或活动状态而跳过的项。

默认清理只处理当前用户、扫描后重新核验的三类候选，不扩展到其他用户、父工作区或相邻路径。备份后删除必须使用固定 T1 路径并完成校验；工作树迁移必须按关联组移动全部内容、修复 Git 登记和引用，并保留原路径软链接。

## 9. 平台动作与路径保护

默认直接删除组使用永久删除以实际释放空间；执行前再次检查真实路径、所属用户、链接属性、活动进程和默认策略白名单。归档会话必须先完成 T1 快照和校验；worktree 迁移完成后本机只保留原路径软链接。用户数据默认不永久删除。

路径保护必须同时限制：

- 目标位于当前授权的用户 Codex 根内，或位于已确认的 Codex workspace/worktree 内部；目标不能等于这些根目录；
- 目标匹配允许的完整目录类型；
- 目标不是源代码、配置、数据库、认证、活动会话或用户文档；
- 目标不是符号链接、junction、alias 或 reparse point；
- 解析后的路径没有越界。

任何检查失败都要停止该项并保留其他数据，不扩大删除范围。不要清空废纸篓/回收站来“确认释放空间”。

## 10. 操作后核验与恢复

每个用户、每个平台和每类动作分别核验：

- 默认组是否按对应策略完成永久删除、T1 备份后删除或 T1 移动并保留原路径软链接；
- 未授权路径仍存在；
- 工作区/worktree 根、sessions、活动任务、源代码、Git 状态、配置和备份未被改变；
- 实际释放空间与估算差异；
- 没有活动进程继续持有已删除文件；
- 归档备份仍可读取，worktree 的 T1 manifest 和内容校验通过，恢复路径和限制已记录。

空间没有立即释放时，只检查打开的已删除文件、平台文件系统回收机制和系统快照；不自动删除快照或停止备份系统。恢复时保留原备份，先停止相关写入，再恢复精确文件，并说明应用索引可能需要重建。

## 11. 完成报告

真实检查缺口应继续做用途分析（`purpose_analysis`）：复用批次身份、计数、项目和双向路径引用，限定读取头尾样本、重试读取目录。单独报告用途、上下文推断/实际证据、剩余问题、读取失败或变化、当前使用状态未检查以及保留/核实建议。容量遍历不因用途分析而提前结束；若另行启动用途分析，独立子进程总预算 120 秒，最多并行四个目标，单目标默认限时 5 秒；准备、读取、引用索引和汇总共用截止时间。阻塞目标超时后继续给其他目标检查机会，超时未返回的目标仍列为未检查；引用索引未完成时不能把空列表解释为没有依赖。样本和目录重试不消除原覆盖缺口，不输出原文，不跟随跨卷/符号链接。所有分析记录只读，主/子服务均拒绝其获得删除权限。

用户明确授权的每日检查使用独立包中的 `scripts/daily_codex_health.py`。它只扫描当前账号内已确认的 Codex 根，并与手动扫描共用 1200 秒完整扫描预算。产品自动化要在覆盖安装并获得单独授权后，通过宿主实际入口创建或更新；没有入口时记录阻塞原因，不用 launchd、crontab 或内部状态文件代替。日常检查不执行删除；小型文件头及内容重复校验未做时必须明确标记未检查，不作为相应内容校验的验收。生成报告使用固定工作目录，保留最近 30 次摘要；超时/失败保存失败信息并保留最近成功摘要。系统命令超时后不无限等待内核阻塞子进程退出；如果容量结果已经写出，失败记录继续提供已测容量和部分报告，同时保留上一份成功摘要。失败状态不能推断为无占用。扫描范围、文件类型识别和内容校验是不同覆盖维度。

报告必须包含：

- 平台、系统账号和 home；核验到的每个 Codex 根、来源依据，以及被排除的容器/云路径/卷和原因；
- 遍历、来源发现、项目关联、活动/引用、计划和报告阶段耗时；总扫描时长、1200 秒预算状态、覆盖是否完整及每个缺口；
- 候选总数、按类型和风险分类的大小；
- 最大的三项保留内容：精确位置或任务、用途证据、逻辑字节、分配字节、保留原因和仍缺少的清理/迁移条件；父子路径与硬链接不得重复计算；
- 每个实际处理的精确路径、动作、用户、释放空间和恢复方式；
- 归档备份路径、T1 快照 ID、真实文件数量、总字节数和校验结果；
- 实际删除/备份/迁移的数量与容量，以及本机可用空间实测前后值和带正负号的变化；
- 明确声明未触碰的工作区/worktree 根、活动会话、未授权用户数据、源代码、配置、认证、Git 状态、废纸篓/回收站内容和系统快照；
- 如果空间未立即释放，说明打开句柄或平台回收机制；
- 未处理项及其具体原因。

### 11.1 每日与手动报告的格式、对账及处理建议

本节服从 SKILL.md 的“必须包含按位置或任务的版本”和“永远在对话框内汇报”：所有结论、方法、容量明细、证据及验证结果直接在当前对话中提供，不以文件或链接交付。每次查账首先说明扫描日期、统计子集和是否重扫，必须包含「位置或任务｜占用｜具体是什么、为什么产生」表格，必要时加判断依据。用途分类版可追加但不能替代前表，两版不得相加。没有实际的新旧测量时不强行制作变化表。下面的变化表要求仅适用于确有可比较数据的情况；所有格式都不能把逐项调查改成标签替换。

在聊天中直接交付下面三类表格；HTML 只作补充。沿用这些通用规则，不把特定项目、历史路径或历史容量写成特例。

1. **空间变化表**：每行包含指标、上次值、本次值、变化及判断；列出可用空间、已扫描文件占用和 Codex 相关占用，并在指标中注明逻辑大小还是文件分配量。标明两次测量时间及覆盖是否可比较；后来单独测得的可用空间另行标时，不能与旧文件清单混成同一次测量。占用上升、可用空间下降用红色／🔴，占用下降、可用空间上升用绿色／🟢；颜色依指标好坏判断，不能一律把正数涂红。
2. **增长来源表**：按有证据的项目与用途归组，列出组成、数量（已知时）、增长量及证据。用「安装包修改时留下的解包与签名测试副本」这类人话解释是什么、为何产生，不用路径或 unknown 标签代替说明；路径用有含义的链接标签。只在同一范围、同一大小口径和可比较覆盖下求和，避免父子目录、硬链接、备份和跨卷重复相加。未保存历史细项或上次漏读的部分明确显示尚未定位／不可比较／新增覆盖，不填成零。
3. **处理建议表**：分别列「建议安全清理」「先备份再删」「保留」「暂不处理」，每项说明内容、占用、判断证据、保留对象及条件。可再生成旧构建和已核实冗余副本须记录源码／恢复来源、完整目录边界、引用及使用状态；内容相同本身不授予删除资格。未核实项写清具体缺少的证据，不笼统让用户自行判断。备份项说明需要校验，指定备份目的地仍为 T1；未实际备份不能声称已有备份。表后给出优先建议，以及本次实际移动／删除项数、动作和实测空间变化；只读检查写「删除 0 项，未执行释放空间操作」，不能把估算写成实际释放。

**数字与单位**：所有展示的容量、增减量、耗时和百分比保留两位小数，使用十进制容量单位；每个数字紧跟完整单位，不能只放在标题或表头。例如 `67.34 GB`、`减少 20.26 GB`、`6.19 GB`、`331.11 秒`、`4.30%`；不写裸数或缩写 `G`。同一行前后比较使用相同单位，数值太小时换成 MB／KB，避免将真实小量四舍五入成 `0.00 GB`。原始字节仍完整保存，先用原始值计算差额／合计再格式化。文件／目录／问题数量用整数加计数单位；日期、时刻、版本、哈希及标识保持原格式，时刻与容量分列。

**增长告警与未定位差额**：明显增长是独立告警条件，不依赖是否低于剩余空间警戒线。按已有通知规则，默认可核验增长至少 `2.00 GB` 或可用空间继续明显下降时提醒；低于 `20.00 GB` 是另一个条件，不能据此淡化短时间大幅下降。全卷可用空间变化与已扫描文件分配变化涉及不同范围及 APFS 共享语义，差额只表示待解释的对账差，不能编造为某项目、系统或其他账号的占用。逻辑增长、文件分配量、估计候选量和实际释放量分别说明。若证据只解释部分增长，报告已定位组成、尚未定位差额、限制与下一步只读检查，不宣称已全部定位。

聊天使用红／绿标记和文字方向；HTML 的每日检查摘要与变化表采用相同好坏语义，未知或不可比较用中性说明。处理建议的颜色不能成为动作权限。报告格式更新不扩大扫描、备份或删除范围，新增只读分析项保持空 `trash_paths`，每次实际处理仍按 §8–10 核验与授权。

## 12. 报告视觉方案

独立包不在运行时读取父 skill。生成清理报告或 dashboard 时，使用包内 `scripts/report_theme.py` 中已固定的 Lieflat Charts Wire 黑灰底、梅子绿/橙色变化语义、2×2 图表结构、F11/F2/G10 视图、结论优先的报告顺序、一次性视口懒加载和本地服务路径白名单；父入口只做兼容转发。

每日检查摘要和空间变化表的红／绿语义按 §11.1 执行；这是用户指定的报告层规则，其他图表保持既有视觉体系。

清理专属内容只新增数据维度：用户、平台、产物类型、来源证据、风险、可恢复性、精确子路径和实际释放空间。清理候选比例条按各类别内部最大产物缩放，使用中性灰，不用新的颜色；工作区根目录和源代码只作为受保护上下文展示，不能渲染为可删除卡片。
